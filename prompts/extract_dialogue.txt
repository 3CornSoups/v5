Task: Analyze the user's intent and multimodal context to extract ONLY genuine spoken words: visible dialogue, character voiceovers/inner thoughts, or independent narration/explanation. Speech Type Classification (CRITICAL):
1. `dialogue`
   - A visible character physically speaks/sings/whispers/shouts the words in the scene.
   - `speaker_visible=true`, `lip_sync=required`.
2. `voiceover`
   - The voice belongs to an existing visible/referenced character, but is delivered off-screen as voiceover, memory, or inner thought.
   - The character must NOT mouth the words.
   - `speaker_visible=true`, `lip_sync=closed`.
   - `character_match` should bind to that existing subject/picture when grounded.
3. `narration`
   - An independent narrator, commentator, explainer, documentary voice, or disembodied announcement provides the words and is not a visible character.
   - Never invent or visualize a narrator person.
   - `speaker_visible=false`, `lip_sync=none`.
   - Use a stable audio identity such as `旁白`, `Narrator`, or the explicitly stated voice description.

- Extract only actual spoken wording explicitly present in the intent. Preserve every character and punctuation mark verbatim.
- Visual descriptions, style tags, physical keywords, camera instructions, and phrases such as "lips moving as if speaking" are NEVER dialogue.

- "No subtitles" does not remove spoken dialogue, voiceover, or narration.
- Do not infer narration from ordinary descriptive prose and do not author missing narration copy.
- Do not invent a visible host, presenter, or narrator to satisfy an off-screen narration request.
- GLOBAL VOICE TIMELINE (HARD CONTRACT): scan the user intent strictly from top to bottom and append every audible event immediately when it appears. Dialogue, character voiceover/inner thought, and independent narration/announcement all belong to ONE shared chronological `dialogues` array. Never group, sort, or regroup entries by speaker, speech_type, character, scene importance, or audio asset.
- The array order must exactly match source occurrence order, including repeated identical lines. A later narration/voiceover/dialogue event may never move ahead of an earlier event of another type.
- Assign stable speaker IDs in first-vocal-event order on that unified timeline. Reuse the same ID for the same source.

Output JSON only (no markdown, no codeblock, raw JSON only):
